## 3. 三条**必须讲**的创新点（这是 15% 创新分的抓手）

### ① 把"批 rank 融合"改写成"逐图 ECDF"（最硬的一条）

- **难点**：提交文件用的是 `rank(x)`——**在 20000 张里排名，单张图算不出来**；而交付标准要求 `POST /predict` **单张调用**。
- **做法**：把 rank 改写成逐图可算的 **ECDF**：
  `ecdf(x) = ( searchsorted(left, x) + searchsorted(right, x) + 1 ) / 2 / (n+1)`
- **效果**：在那 20000 张测试图上**恒等于** `rankdata(method='average')/(n+1)` ⇒ 实测**逐图重建提交文件 `spearman = 1.0000000000`**。
- **细节里有个坑值得讲**（体现技术深度）：`+1` 不能少。少掉就恒小 `0.5/(n+1)`，在并列组大的量（尺寸先验只有 43 档）上会让查询值落到并列组**另一侧**，凭空产生 ~3.5e-3 的跳变。

### ② 槽内**多源注入**，而不是在弱侧替换

- 起初发现一个反直觉现象：`corr(基底, 主分量 cliph_rerun) = 0.9758` ⇒ **基底几乎就是那一个分量**，改 35% 那一侧几乎无效。
- 于是改成**往主槽内部注入独立强分量**：
  - `gpp`（SigLIP2 + GenImage++，**LB 实测 0.9054**）与 `cliph300k`（换数据到 302k）**彼此相关仅 0.7403**，且与主分量 0.78~0.79；
  - 槽 = `0.65·cliph_rerun + 0.15·cliph300k + 0.20·gpp`。
- 关键判据：**"低相关"只是必要条件，"分量本身必须强"才是充分条件**——历史上"低相关但极弱"的 `nprft`（0.61）加进去反而掉 0.0017。

### ③ 尺寸先验：把"数据构建偏差"变成可用信号

- 观察：**AI 生成器输出尺寸固定，真实照片尺寸多样**（512×512 假图率 92.2%、1024×1024 83.0%、而 1024×683 仅 6.9%）。
- 严格 5-fold CV：**OOF AUC = 0.8247**，与模型分量**图片级相关仅 0.146**。
- 用法：**后融合**（从官方样例学），**不投喂模型**（外部训练集尺寸分布不同，会把错误先验学进模型）。
- ⚠️ **合规性要主动讲**：这属 shortcut learning（利用了数据集构建偏差），按现行规则不违规（用的是官方允许的样例标注数据），但我们**主动在报告与交付说明里披露**。

## 5. Q&A 追问预案（评委点名的五类问题）

### Q1「实验结果可靠性」——最可能被追问，务必背熟

> **问**：你们说镜像能复现 0.918887，凭什么说可靠？

**答**（三层）：
1. **提交文件本身逐位可复现**：只用交付包里的 10 个冻结 CSV，`spearman = 1.0000000000`、最大绝对差 `7.5×10⁻⁵`（浮点舍入）。**这条不需要 GPU、不需要权重**，评委可当场验。
2. **镜像与提交文件的一致性**：官方测试集 200 张均匀取样，**`spearman = 0.999165`**；8 个分量中 7 个 0.9961~0.9999。
3. **偏差已量化到"可忽略"**：翻转样本对的分数间距中位数 **0.0066**，而全体样本对是 **0.2933**（小 44 倍）⇒ 翻转几乎只发生在"近乎并列"的样本对上，AUC 影响 ≤1e-4 量级。

> **追问**：那为什么不是 1.000000？

**答**（如实）：两条链路的**推理数值路径不同**——
- 离线出 CSV 用 **bf16 autocast + 批推理（BS 8~32）**；
- 镜像按标准**单张调用**（BS=1）且用 **fp16**（为控制镜像体积与显存）。
其中**批大小我们做了单变量实测并排除**（同一权重 BS=1/4/8/32 输出完全一致）；**精度**这一项我们未能单独分离，如实写进了给组委会的说明（`docs/04`）。

> **追问**：还有一处更大的差异？

**答**（主动认）：是 `img_bigg_s384_retrain` 这个分量（权重 10.71%），它与冻结 CSV 的一致度 **0.9785**，低于其余 7 个。原因已定位：**产出该 CSV 的 `best.pt` 与镜像内打包的权重是同一配方下的两次不同训练**（两个脚本指向同一 `runs/clean_s384/best.pt`，实测两者输出相差**远超数值抖动**——最大绝对差 0.9977，即存在一边判 ~1.0、另一边判 ~0.0 的样本，唯一自洽的解释是该文件被重复执行覆盖）。**该项对最终排序的影响经精确消融为 +0.000382（万分之四以下）**，且我们把这条差异主动写进报告，而不是藏在"通过"的结论后面。

### Q2「跨模型泛化能力」

> **问**：你们的方案大量依赖测试集转导（transductive），换一批图还行吗？

**答**（分层，别硬吹）：
- **诚实的边界**：8 个分量里 **4 个（cliph 族）是"用测试集软标签蒸馏"的学生**，它们**在这 20000 张上的表现不代表对新数据的泛化能力** —— 这是我们刻意的转导设计，已写进报告 §5 与提交说明 §6。
- **泛化的部分**：另外 4 个分量是**纯监督**（`cliph300k` 302k 真标签、`gpp` GenImage++ 78k、`bigg_rerun2/3`、`s384_retrain` Tiny 28.8k），它们不依赖测试集；且**尺寸先验**是从官方样例学的分布，对同源新数据仍有效。
- **可迁移的做法**：真正可迁移的是**方法论**——① 多骨干多视角融合；② 逐图 ECDF 化的 rank 替代；③ 用外部生成器数据造"独立分量"。换数据集时**重跑转导那一层**即可。

### Q3「对抗鲁棒性」

> **问**：测试集含对抗样本，你们怎么应对？做了对抗训练吗？

**答**（不要吹）：
- **没有做对抗训练**（如实说）。我们的稳健性来自**多视角互补**而非对抗训练：
  ① 3 个异构骨干（CLIP-H / bigG / SigLIP2）对同一种扰动的敏感方向不同；
  ② JPEG 质量增强（q55-95）让模型见过重压缩；
  ③ 尺寸先验使用**与生成痕迹无关**的维度（尺寸分布），对像素级扰动天然不敏感。
- **可以补强**（如果评委问"下一步"）：对 JPEG 重压缩、缩放、轻微裁剪做 TTA；对抗训练（PGD）作为后续工作。

### Q4「方案创新性」

> **问**：和通用 AIGC 检测器比，你们新在哪？

**答**：三点，按"可验证"排序 ——
1. **逐图 ECDF**：解决了"批 rank 无法服务化"这个**工程上真实存在、且论文里很少讨论**的问题，并给出 `spearman=1.0000000000` 的强验证。
2. **转导蒸馏 + 纯监督多源注入的组合**：我们用 5 个对照 run 证否了"换教师能造出独立分量"，并给出**独立性来自"监督方式"而非"数据规模"**的结论（28.8k 与 302k 的独立性几乎相同：0.8012 vs 0.7785；而一旦掺入教师软标签立刻退化到 0.9315）。
3. **尺寸先验与模型的解耦**：把它做成**后融合**而不是训练特征，避免污染模型。

### Q5「产业落地前景」

> **问**：这套东西能落地吗？成本多少？

**答**：
- **形态适配**：单容器、离线、非 root、三探针齐全 ⇒ 可直接接入现有推理平台；`POST /predict` 是标准单张 HTTP 接口。
- **成本**：单张 **0.31 秒**、显存 **~9 GB** ⇒ 一张 4090 级别卡即可支撑约 **3 QPS**；横向扩容只需复制容器。
- **局限（如实说）**：① 8 个分量串行前向，延迟换精度；② 转导蒸馏部分**必须针对目标分布重训**，不是"拿来即用"；③ 尺寸先验依赖"生成器输出尺寸固定"这一当前事实，生成器普遍改为自适应尺寸后该信号会衰减。

## 6. 评审可能"挑刺"的地方 + 我们的答法（**主动准备，别被问住**）

| 潜在质疑 | 我们的答法 |
|---|---|
| "你们用了尺寸先验，算不算作弊？" | 用的是**官方允许的初赛样例标注数据**，不违规；但方法上属 shortcut learning，我们**主动披露**（报告 §1.5、提交说明 §6.1）。且它只占最终权重 **20%**，去掉后仍有 0.908+ 的水平。 |
| "转导蒸馏用测试集标签，不算过拟合吗？" | 是转导（transductive），不是用测试**标签**——用的是**无标签测试集的分布** + 教师软标签。这是半监督/转导学习的标准做法；但它确实**不提升对新分布的泛化**，我们如实写明。 |
| "8 个模型太臃肿，工程上不实用" | 三个骨干**共享**、8 个 LoRA 每个仅 ~100 MB；镜像 19 GB（其中骨干 fp16 占 9.3 GB）。若追求延迟可只保留主槽 5 个分量（精度损失已在报告 §9 量化）。 |
| "为什么不做更大的模型？" | 做过对照并**得出反直觉结论**：同骨干同预处理下，28.8k 数据得 **0.9904**，而 302k 数据只有 **0.7234**——**数据质量/同源性**比规模更关键（报告 §4、§9.7）。 |
| "交付镜像有没有可能跑不起来？" | 已做**独立复检**（不需要 Docker、不需要 GPU 的 chroot 复检 + 真 GPU 起服务）：以非 root 用户 `appuser` 读取镜像内全部权重（`UNREADABLE 0`）、三探针全 200、`/predict` 返回 `code=0`。证据见 `evidence/`。 |
