## 01｜AI生成内容鉴别

## 02｜少标签与分布变化下的检测任务
计划：40秒；累计 00:10—00:50。
　　检测任务存在三个难点。第一，标签少，有限的人工样例很难覆盖各种生成方式。第二，数据会变，换一个来源，或者经过压缩、改写，检测线索就可能变化。第三，实际使用时，系统需要一张图、一段文本地给出结果。
　　所以，我们的思路是：先用预训练模型和人工标签建立检测基础，再利用无标签数据适应当前目标集合，同时设计逐条推理的方法。下面看这三个环节怎样连接起来。

## 03｜两条独立检测链，共同的方法主线
计划：45秒；累计 00:50—01:35。
　　请看这张全景架构图。上面是图像链，下面是文本链。沿实线从左往右看，是单样本输入、预处理、模型分支、融合和各自的输出。虚线表示训练与辅助信号。图像有三类骨干、八个分量；文本用两个基座、三组适配器。
　　图像和文本各自训练、各自输出。两条链共用的方法思路是：借助预训练模型提取特征，用软标签学习目标数据，再组合不同模型的判断。也就是从数据、训练到融合，最后接到逐条推理接口。我们先看图像侧。

## 04｜图像训练：转导学生与监督分量
计划：70秒；累计 01:35—02:45。
　　图像训练有两类来源。上面是转导蒸馏。这里的“转导”，就是把当前两万张无标签目标图像也用于训练。教师先给出软标签，四个CLIP-H学生再结合一千张官方标注学习这些判断。不同训练配置提供多组学生输出。
　　看中间的放大图：骨干权重冻结，LoRA低秩旁路与它并行，再相加、进入分类头。训练只更新LoRA和分类头，加入JPEG增强；监督支路还使用水平翻转。这样减少了更新参数，推理仍要运行完整骨干。
　　下面是独立监督训练，包括bigG三个分量和SigLIP2，使用Tiny-GenImage、GenImage++，并加入官方八百条训练、两百条验证。两类来源补充目标域针对性和视觉多样性。下一步，把八路输出融合。

## 05｜图像融合：三槽计算与逐图ECDF
计划：80秒；累计 02:45—04:05。
　　八路分数不能简单相加。有的模型分数集中在中间，有的接近零或一，直接加权，实际作用就会受到分数尺度影响。
　　我们的做法是先做ECDF映射，把每一路分数转成参考集合中的排序位置，再分成图中的三个槽。四个CLIP-H和SigLIP2等权进入主槽，两个低分辨率bigG进入第二槽，高分辨率bigG进入第三槽。主槽占四分之三，其余权重见图中公式。
　　三槽组合后，再按八比二加入尺寸先验，最后做一次ECDF映射。尺寸先验利用宽高、像素和文件大小，补充图像规格信息。但这类线索依赖数据分布，换场景后要重新评估。
　　推理时，参考表已经固定，一张图片也能查到自己的排序位置。因此，这个输出是检测分数，不能直接理解为“有多少概率是AI生成”。下面看这种组合的效果。

## 06｜图像效果：融合性能与分量互补

## 07｜文本：目标域自训练
计划：80秒；累计 05:05—06:25。
　　文本侧同样是一千条官方标注，加两万条无标签目标文本。关键是把已有检测分数变成训练信号。
　　请沿左侧实线看：上一代检测器先给两万条文本打分，分数转成排名，再由sigmoid生成软标签。左侧八百条官方硬标签汇入加权损失，软标签同时带上置信权重。冻结语言基座后，更新LoRA和分类头。
　　右边实线表示软标签，范围约零点一二到零点八八；虚线表示权重，中间最低、两端最高为一。官方硬标签权重为二，提供真实监督。这些权重直接作用到二元交叉熵损失。
　　流程图右侧，中间的每折两百条只用于验证，AUC选择检查点；下方的五折折外预测用于融合选型。这样利用目标域数据，也减少中间样本的监督强度，但不能保证教师错误不会传播。下面看最终模型。

## 08｜文本：两基座，15个适配器
计划：70秒；累计 06:25—07:35。
　　最终方案以Qwen2.5十四B为主、七B为辅。请从模型树上方往下看：两个共享基座，分出三组五折。十四B主分支有五个适配器；七B两个辅助分组各有五个，共十五个。两组七B并不是一次十折验证。
　　推理时，基座常驻，适配器依次切换。十四B运行五次，七B运行十次，底部先分别聚合，再按百分之九十和百分之十汇合。
　　再看右边的结果：十四B五折组合已经达到约零点九八一一，加入七B后约为零点九八一三，提升约零点零零零二三。这个收益需要和额外计算一起衡量。因此，辅助分支是否保留，要看它能否补充主模型的判断。下一页解释同一套模型如何处理整批数据和单条请求。

## 09｜文本：批排名与单条推理
计划：60秒；累计 07:35—08:35。
　　这里有两条计算路径。左边沿三个rank节点往下看：各组预测先转成排名百分位，再以九成、百分之五、百分之五汇合，最后对整批结果重新排名。
　　右边从顶部输入往下看，在线服务一次只收到一段文本。十四B的五个logit，也就是模型原始输出，先平均，再做sigmoid；七B的十个logit也共同平均，再做一次sigmoid。两侧分数最后才按九比一加权。
　　这个顺序很关键，平均和sigmoid不能交换。这两条路径使用的计算空间不同，也就不能直接认定检测效果相同。在线输入还会截断到五百一十二个token，因此实际评测要对应服务的计算方式和输入条件。下面汇总两条链的结果。

## 12｜检测效率与资源配置
计划：75秒；累计 10:35—11:50。
　　部署时，两条链都共享基座、顺序切换分量。图像完成八路打分，文本执行十五个适配器前向。服务用互斥锁保护共享参数，避免请求相互覆盖。
　　图像的已有测试，是两百张图片顺序HTTP请求，共四十七点二秒，平均每张零点二三六秒。文本是五条测试输入，以短文本为主，其中包含空串，HTTP均值零点六八秒。两组条件不同，文本测量来自宿主GPU，不能直接比较，也不能据此推算并发吞吐。批量预测还需要单独测量完整集成的总耗时。

## 13｜从检测分数到内容审核辅助
计划：60秒；累计 11:50—12:50。
　　我们的方案特点，是把异构表征、目标域软监督和逐条推理组合起来。它既利用不同模型的判断，也把目标数据的信息纳入训练和融合。
　　应用上，可以让图片和文本分别评分，帮助内容平台、素材筛查安排审核优先级，再由人工处理高风险和边界内容。这是我们考虑的应用路径。
　　落地时，阈值要根据误报成本来选，不能直接设为零点五。如果场景更重视保护正常创作，就先确定可接受的误报率，再看生成内容的召回。同时监控来源、尺寸、语言和风格变化，必要时重新校准模型与参考表。我们计划先用代表性的业务数据评估，再做小范围试点。最后总结三点。

## 14｜核心结论
计划：30秒；累计 12:50—13:20。

## 注解汇总（按页对应，不口播）

### 通用符号速查
· σ = sigmoid 1/(1+e^−z),把任意实数压到 0~1;σ(0)=0.5
· logit = 未过 sigmoid 的原始分;文本训练与推理都取 logits[:,0](第 0 维)
· BCE = 二元交叉熵,衡量预测概率与目标值的差距;加权 BCE = 逐样本损失先乘权重 w 再按样本数取平均
· 权重 w = 该样本在损失里的乘数(图像硬标签 4.0 / 软标签 1.0;文本硬标签 2.0 或 4.0 / 软标签 conf)
· rank01 = 名次/(N+1),最小 1/(N+1)、最大 N/(N+1),不贴 0/1
· ECDF = “分数 ≤ x 的占比”,与 rank 数值相等,可预存查表 → 支持逐条查询
· ρ = Spearman 秩相关;AUC = 排序判别力(0.5 随机 / 1.0 完美)
· checkpoint = 训练过程中存下的一版权重;每折按验证 AUC 选最好的一版
· adapter(适配器)= LoRA 增量文件,挂在冻结基座上,切换即换模型
· fp32 / fp16 / bf16:fp32 标准;fp16 快但范围窄;bf16 范围同 fp32、尾数短

### 命名速查
· p4 / p42 / p43 = 14B 侧的训练谱系名;p4 是最终采用的那条
· r3a / r3b = 第 3 轮蒸馏的两个随机种子;rN 的 N 与伪标签代次一致(r2 = 第 2 代)
· pseudo_best_v1..v4 = 四代伪标签,分别来自 0.973656 / 0.978284 / 0.980896 / triple 14B;最终 14B p4 用 v2
· cliph / bigg / s384 = 图像三个槽;s384 槽的骨干仍是 CLIP ViT-bigG-14 @384,不是 SigLIP
· anchor = 图像教师混合线 0.70·rank(cliph50) + 0.30·rank(siglip030),当时 LB 0.900099
· SPAI = 历史基线名的一部分,仓库无定义,按原名引用

### 两个易混的“43”
· 图像侧 43 = 官方 1000 张里的 43 个不同分辨率(尺寸先验的桶)
· 文本侧 43 = 教师候选池的 43 路信号(其中实际带权 6 路,public 家族 11 路权重为 0)

★ 这张是全景图:上面图像链、下面文本链,两条链独立训练、独立输出,不存在联合图文推理。

· 文本链四段:分词(最多 512 tokens)→ 模型与适配(Qwen2.5-14B 5 个适配器、7B 两组共 10 个)→ 分数融合(分基座均值 → sigmoid → 14B/7B 按 9:1 融合)→ 输出文本分数。
· 三种数法别混:按骨干 4:3:1;按视角 4:2:1:1;按槽 5:2:1。三者数字都对,尺子不同。
· 【图里“目标域蒸馏”与“公开监督”是什么意思】目标域蒸馏 = 教师给目标集 20000 条打软标签、学生照着学(用上了待测数据本身);公开监督 = 只用公开数据集(GenImage++ / Tiny-GenImage)的真标签训练。
　【有什么意义】前者让模型对齐当前目标分布(转导),代价是这批评测数据不再是“没见过”;后者不碰目标集、泛化更干净但针对性弱 —— 两类分量互补,本身就是“异构”的一部分。
· 【口径】15 个适配器依附 2 个基座,不是 15 个完整模型;8 个图像分量共享 3 个骨干,也不是 8 个模型。

### 第 04 页｜图像训练：转导学生与监督分量
★ 上面是转导蒸馏(4 个 CLIP-H 学生),下面是独立监督(4 个互补分量);两条路线的区别在“用不用目标集软标签”。
· 【上半区的训练数据】目标图像 20,000 条走教师软标签;官方样例 1,000 条是硬标签、权重 4。两条数据一起进损失。
· 【“权重4”是什么意思】它是该样本在损失里的乘数 —— 不是概率、也不是类别权重。实现是 loss = mean(wᵢ · BCE(zᵢ, yᵢ)):逐样本损失先乘权重,再对全部样本取平均。
　图像侧:官方 1000 条 × 4 = 4000,测试集 20000 条 × 1 = 20000 → 硬标签占总损失质量约 16.7%(约 1/6);若不加权只有 4.8%(1/21)。
　【有什么意义】把真标签的话语权从 1/21 抬到 1/6 —— 伪标签是自己模型给的,只有这 1,000 条是外生监督,不能被 20,000 条软标签淹没。
　【对照】文本侧没有 2 就不对:14B 自训练用 2.0(硬标签占比 9.8%)、7B/1.5B 蒸馏用 4.0(17.8%),因为文本软标签还要乘置信度(均值约 0.738)。纯监督的 4 个图像分量用普通 BCE、没有逐样本权重,所以 2/4 的说法对它们都不适用。
· 【图中“低秩旁路 LoRA · A → B · r=32”是什么意思】主路是冻结权重 W(骨干内线性层,不更新);旁路并联两个小矩阵 A、B,输出按 (α/r)·BA 加到主路上,r=32 是秩、决定旁路宽度。
　【有什么意义】可训参数因此只有原模型的 0.5%~2.5%(图像侧 15.73M),既保住预训练知识,又让 8 个分量共享同一副骨干 —— 镜像体积与显存才可控。
　【分类头】接在骨干之后、新初始化的一层(此处可训练),负责把骨干输出的向量映射成一个检测分数;它不随预训练权重走,所以必须与 LoRA 一起保存,否则分数复现不出来。
· 【“加权 BCE”是什么意思】BCE(二元交叉熵)= 衡量“预测概率离目标值有多远”;“加权”= 逐样本损失先乘系数 w 再平均。写法:图像用 F.binary_cross_entropy_with_logits(logit, tgt, weight=w)(cliph_rerun.py:182),文本用 BCEWithLogitsLoss(reduction='none') 后 (l*w).mean(),两者等价。
　【一个容易踩的细节】reduction='mean' 是按【样本数 N】平均,不是按权重和 —— 抬权重会整体放大损失尺度(近似调大学习率),与“不除以权重和”是同一件事。
· 【下半区四个互补分量】bigG@224 × 2(r=16、α=32)、bigG@384 × 1(r=32、α=64)、SigLIP2 × 1(r=16、α=32);各自用 Tiny-GenImage 28.8k 与 GenImage++ 78k,每个都冻结骨干 + LoRA + 分类头。
· 右下角三个数:官方样例 800 训练 / 200 验证;JPEG 增强(监督支路另有水平翻转);W′ = W + (α/r)BA 是 LoRA 的更新式(W 冻结,A、B 是仅有的可训矩阵)。
· 页脚“8 个分量 = 4 + 2 + 1 + 1”是按【视角】数(转导 4 + bigG@224 2 + bigG@384 1 + SigLIP2 1);按骨干是 4:3:1。

### 第 05 页｜图像融合：三槽计算与逐图ECDF
★ 顺序是:逐分量 ECDF → 三槽加权得到 base → 与先验合成 z → 只对 z 做一次最终 ECDF;base 中途不做 ECDF。
· 左段“8 个分量输出 → 逐路转换”:每个分量各自一张 ECDF 表,把自己的原始分换成百分位。
· 公式 s_i → p_i = F_i(s_i):逐符号读 —— i = 分量编号(1~8);s_i = 该分量的原始分(八个分量量纲不同);F_i = 该分量【自己那份】ECDF 表;p_i = 查出来的百分位(0~1)。
　【作用】把量纲各异的原始分统一到同一把尺子,这是后面能按权重相加的前提。
· ECDF 式 F_ref(x) = (lo + hi + 1) / (2(N+1)):逐符号读 —— ref = 参考数组(该分量在 20000 张上的分数);N = 20000;lo = 参考数组里【严格小于】x 的个数;hi = 【小于等于】x 的个数(并列都算进来)。
　分子 lo+hi+1 = 并列样本【平均秩的两倍】:并列时取 (lo+1+hi)/2,通分即 (lo+hi+1)/2;分母 2(N+1) 里的 2 正是通分带出来的。所以整式 = 平均秩 ÷ (N+1),与 rankdata(x,'average')/(N+1) 逐位相等。
　【那个 +1 不可省】省掉会出现 0.5/(N+1) 的常数偏移(排序不变,但数值不等)。数值验证过:四种数据(含 19957 个并列)最大绝对差都是 0。
· 中段“3 槽聚合与权重”:主槽 3/4(4 个 CLIP-H + SigLIP2,五路百分位等权平均)、bigG224 槽 1/7(两路等权平均)、bigG384 槽 3/28(只有一路)。
　【为什么这么分槽】依据是“是否同配方只换随机种子”:同配方换种子的 CLIP-H 四路 ρ≈0.96,几乎是同一模型 → 放同一槽内平均降方差;跨架构(↔SigLIP2 0.7914、↔bigG384 0.7091)明显更低 → 携带新信息 → 单独成槽、单独给权。
　【作用】槽内平均 = 降方差,避免同一份信息被重复计分;槽级加权 = 按互补性分配话语权。
· base · 三槽加权和 = (3/4)m_H + (1/7)m_B + (3/28)m_384,三数相加正好为 1。
· 尺寸先验 prior:只用图片规格算出的一路信号(0.4 桶查表 + 0.6 GBM,各查 ECDF → 混合 → 再 ECDF)。
　【是什么/有什么意义】它与模型分数的相关只有 0.146、自身 OOF AUC 0.8247 —— 又强又近乎独立,才有资格占 20% 权重补模型盲区;若相关也到 0.9,给 20% 就是重复计分。
· 融合分 z = 0.8·base + 0.2·prior:【作用】后融合 —— 不把外部尺寸先验学进模型,权重可事后调、可解释。
· 右段“固定参考分布查询”:单图分数 x → 查表 → 百分位;参考表固定,无需实时批排名。
　【作用】让百分位【逐图可算】—— 服务端一次只收到一张图,算不出全局排名;这个式子只依赖预算好的参考表,所以镜像能对单张出分,而且与离线批 rank 排序一致。它就是把“交付形态(逐条)”与“算法(全局排名)”接上的那座桥。
· 最终 ECDF 查询 F(z),单图分数落在 [0,1]:全程只做这一次 ECDF,且只作用于 z。
· 页脚“输出为排序百分位;尺寸先验依赖尺寸与文件属性分布”:后一句是主动披露 —— 先验本质是利用数据集构建偏差(shortcut learning),换生成器或统一尺寸后要重新评估。

### 第 06 页｜图像效果：融合性能与分量互补
★ 三张图都不是“成绩单”,而是设计依据:四个候选说明选型过程,ρ 定分槽,先验 OOF 定 20% 权重。
· 左图四柱(复赛 AUC):0.908114 基线 → 0.916175 基底与权重 → 0.917360 多种子 → 0.918887 监督互补;最后一段 +0.001527。
　【口径】四个候选同时改了基底/权重/训练,属【选型结果,不是单变量消融】;相邻差值只能说明“当时选它”,不能归因到某一个设计。
· 中图 分量秩相关系数 ρ:CLIP-H 六对均值 0.9601;主 CLIP-H ↔ SigLIP2 0.7914;主 CLIP-H ↔ bigG384 0.7091。
　【这张图有什么用】它是【诊断】,回答“8 个分量会不会是重复的、融合有没有意义”,并直接支撑两个决策:
　① 定分槽规则 —— 同配方换种子的 CLIP-H 四路 ρ≈0.96(几乎同一模型)→ 同一槽内平均;跨架构 0.79 / 0.71 明显更低 → 携带新信息 → 单独成槽、单独给权(5:2:1 的依据就在这里)。
　② 诊断转导的代价 —— 掺软标签的分量彼此 ρ=0.9315,而纯监督之间只有 0.8012 / 0.7785:转导蒸馏会让分量趋同、削弱互补性。这也是“独立性来自监督方式,而非数据规模”的实证。
　【别过度解读】ρ 低只代表【互补潜力】,不等于融合必然提升 —— 反例就在同一页:双 14B 种子 0.980896 低于 14B p4 五折 0.981069。

　【这张图的作用】先验模块的体检报告。① 只用图片规格做题就有 0.82 的 AUC → 规格分布确实携带信息;② 两路混合比任何单路都好(+0.0052)→ 0.4/0.6 是试出来的、不是拍的。再结合“与模型分数相关仅 0.146”,才是敢给它 20% 权重的完整依据。
　【必须限定】这是官方 1000 张上的 5 折 OOF 值,只说明这批样例;本质是利用数据集构建偏差,跨来源不一定成立 —— 主动披露。

### 第 07 页｜文本：目标域自训练
★ 左栏是流程,右栏是这套流程的数学细节;核心是“把教师的排序变成带权重的软目标”。
· 左上“上一代检测分数 → 20,000 目标文本”:教师就是【上一代自己那一版最好的提交分数】,不是外部模型 —— 属迭代自举;代价是教师与学生的能力上限绑定,且有偏置累积风险。
· “目标集排序 r = rank/(N+1),并列取平均秩”:r 是教师在 20000 条里的排名百分位(0~1)。
　公式 y = σ[4(r − 0.5)]:逐符号读 —— σ = sigmoid;系数 4 = 拉伸强度;y = 软标签。值域 0.1192~0.8808,【刻意到不了 0/1】,不把教师的高置信判断固化成铁律。
　【作用】把教师的【排序】变成可训练的【软目标】:σ 单调,所以“谁更像 AI”的次序完整保留。
· 公式 w = min(1, 4|y − 0.5|):|y−0.5| = 离中点的距离;min(1, ·) = 上限封顶为 1。
　【作用】让教师【犹豫的样本】自动降权(rank≈0.5 → 权重趋 0),抑制伪标签噪声;排序两端饱和到 1。
　可算的结论:两个分界点 .2253 / .7747 由 |y−0.5| = 0.25 反解;约 45% 的样本(0.2253 + 1 − 0.7747)拿满权重,均匀分布下平均权重约 0.738 —— 由高置信样本主导训练。
· “官方硬标签 每折 800 条 权重 = 2”:这就是文本侧的“2”,与图像侧的 4 不同(见第 04 页对照)。
· “加权BCE mean(w · BCE)”是什么意思:BCE 衡量预测概率离目标值的距离;逐样本损失先乘权重再按样本数取平均。
　【有什么意义】把“这条标签有多可信”直接写进损失 —— 真标签加重、教师犹豫的软标签压到近 0,于是在“真标签少、伪标签多”的配比下,唯一的外生监督不被淹没。
· “每折 200 条验证 AUC选checkpoint”:每个 epoch 末在该折没见过的 200 条上算验证 AUC、取最好一版存档。
　【有什么意义】官方只有 1000 条标注、训练轮数少(1~2 个 epoch),“选点”比早停规则更直接,也避免用训练集自身的表现挑模型。
· “LoRA 学生 适配器＋分类头 → 梯度更新 → 预测”:冻结语言基座,只更新适配器与新初始化的分类头。
· “五折OOF 选择融合方案”:每折验证样本由没见过它的模型打分,用这些折外预测来选融合权重 —— 注意:在同一份 OOF 上反复搜权重,等于把验证集当训练集用,可能高估,所以最终取舍以官方复赛反馈为准。
· 页脚“中点弱监督,排序两端权重饱和;曲线表示公式映射”:右图实线是软标签 y、虚线是权重 w,两条曲线只是公式的可视化,不是实测数据。

### 第 08 页｜文本：两基座，15个适配器
★ 15 = 一个 14B 主分支五折 + 两个 7B 辅助分支各五折;是“两个基座三条谱系”,不是十折或十五折交叉验证。
· 模型树:Qwen2.5-14B → 主分支 5 个 adapter;Qwen2.5-7B → 辅助 A、辅助 B 各 5 个 adapter。
　【谱系名怎么读】p4 = 14B 侧的训练谱系名(脚本 p42/p43 一族);r3 = 第 3 轮蒸馏(适配器 meta.json 写明 labels = pseudo_best_v3);a / b = 同一轮的两个随机种子。所以 p101 脚本里的 ens7 = mean([r3a, r3b]) 就是“7B 两个第三轮种子”的集成。
　【关键配置】r3a / r3b 的 meta.json:base = Qwen2.5-7B-Instruct;labels = pseudo_best_v3;pred = logit_diff。
· 右侧公式 p14 = σ(mean 5)、p7 = σ(mean 10):先各适配器的 logit 取平均,再 sigmoid;最后 0.9p14 + 0.1p7。
　【聚合顺序不能改】σ 与均值不可交换 —— 先平均 logit 再 sigmoid ≠ 先 sigmoid 再平均,顺序不同结果就不同(第 09 页两链路的差异根因)。
· “两个基座常驻;每条文本执行 5＋5＋5 次前向”:15 次前向是单条延迟的主要成本来源,也是效率上的短板。
· 右下候选表(复赛 AUC):早期融合候选 0.978284 → 14B 自训练 0.979964 → 14B 双种子 0.980896 → 14B 五折 0.981069 → 14B+7B 0.981301。

　【别过度解读】页脚写着“双种子未超过五折组合” —— 加分量不保证提升,这是选型结果、不是通用结论。

### 第 09 页｜文本：批排名与单条推理
★ 两条链路聚合的空间不同:左边在秩空间(整批可用全局排名),右边在 logit 空间(逐条只能各算各的),所以不保证同排序。
· 左栏“整批目标集合 · 秩空间”:14B 主分支取 rank r14、7B 辅助 A 取 r_a、辅助 B 取 r_b → 按 0.9 / 0.05 / 0.05 相加 → 再对整批结果重新排名,得到离线检测分数。
　0.05 的来源:7B 那 0.10 的一半,平分给两条谱系。
· 右栏“单条输入 · logit 空间”:14B 的 5 个 logit 先平均(μ14 = mean(5))、7B 的 10 个先平均(μ7 = mean(10)),各自过 σ 得到 p14 / p7,再按 0.9 / 0.1 加权。
　【为什么不能直接照搬离线】线上一次只收到一段文本,拿不到全体样本的分布,全局排名这一步在逐条协议下不可实现 —— 这就是两链路必然有差异的原因。
· 页脚“聚合空间不同,不保证同排序;分支预测已包含各自逐折聚合;在线上限 512 tokens”:
　【分支预测已包含逐折聚合】意思是画图时每个分支的分数已经是它五折的合并结果,不能再用 rank(raw mean) 之类的方式替换。
　【512 tokens】是显式截断、只保留头部,属工程选择而非赛题要求;超长文本的尾部线索会丢,滑窗分段是改进方向但目前没做。
· 【已量化的差异】两链路排序相关约 0.99987,排序发生变化的样本对占 0.10929%(218,571 对);没有复赛真标签,不能把它换算成实测 AUC 差 —— 材料里给的 0.0022 是“正负各半且受影响对均跨类别”假设下的条件性上界,不是实测值。

### 第 13 页｜从检测分数到内容审核辅助
★ 这一页是应用设想与接入方式,不涉及任何已上线能力或客户数据。
· 四步流程:内容输入(图像与文本走独立入口)→ 模型评分(提取生成特征、给连续分数)→ 阈值与分流(按业务阈值安排审核顺序)→ 人工审核(结合场景规则形成最终判断)。
· 公式 s(x) ≥ τ → 重点审核:逐符号读 —— s(x) = 模型给的连续分数;τ = 业务阈值。
　【作用】把【分数】变成【业务动作】:交付的是排序能力,落地要靠阈值分流;而 τ 不由分数决定,要由【业务能接受的误报率反推】。
　【注意】分数未经概率校准,不能直接卡 0.5,更不能把 0.9 解释成“90% 概率是 AI”。
· 下方“业务数据测试 → 阈值校准 → 分布监控”是建议的落地顺序:先在代表性业务数据上定误报率、再标阈值,上线后持续监控分布漂移。
· 页脚“应用设想:内容平台与素材筛查” —— 没有客户、没有生产规模数据、也没有收益或低误报业务指标,不能说成已落地。
