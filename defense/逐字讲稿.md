## 逐字稿（第 01 ~ 14 页）

## 01｜AI生成内容鉴别
计划：10秒；累计 00:00—00:10。
　　各位评委好，我们是南枝大学参赛队。下面汇报我们的AI生成内容检测方案，分别面向图像和文本两个赛道。

## 02｜少标签与分布变化下的检测任务
计划：40秒；累计 00:10—00:50。
　　我们先看任务中的三个难点。第一，标签少，有限的人工样例很难覆盖各种生成方式。第二，数据会变，换一个来源，或者经过压缩、改写，检测线索就可能变化。第三，实际使用时，系统需要一张图、一段文本地给出结果。
　　所以，我们的思路是：先用预训练模型和人工标签建立检测基础，再利用无标签数据适应当前目标集合，同时设计逐条推理的方法。下面看这三个环节怎样连接起来。

## 03｜两条独立检测链，共同的方法主线
计划：45秒；累计 00:50—01:35。
　　请看这张全景架构图。上面是图像链，下面是文本链。沿实线从左往右看，是单样本输入、预处理、模型分支、融合和各自的输出。虚线表示训练与辅助信号。图像有三类骨干、八个分量；文本用两个基座、三组适配器。
　　图像和文本各自训练、各自输出。两条链共用的方法思路是：借助预训练模型提取特征，用软标签学习目标数据，再组合不同模型的判断。也就是从数据、训练到融合，最后接到逐条推理接口。我们先看图像侧。

## 04｜图像训练：转导学生与监督分量
计划：70秒；累计 01:35—02:45。
　　图像训练有两类来源。上面是转导蒸馏。这里的“转导”，就是把当前两万张无标签目标图像也用于训练。教师先给出软标签，四个CLIP-H学生再结合一千张官方标注学习这些判断。不同训练配置提供多组学生输出。
　　看中间的放大图：骨干权重冻结，LoRA低秩旁路与它并行，再相加、进入分类头。训练只更新LoRA和分类头，加入JPEG增强；监督支路还使用水平翻转。这样减少了更新参数，推理仍要运行完整骨干。
　　下面是独立监督训练，包括bigG三个分量和SigLIP2，使用Tiny-GenImage、GenImage++，并加入官方八百条训练、两百条验证。两类来源补充目标域针对性和视觉多样性。下一步，把八路输出融合。

## 05｜图像融合：三槽计算与逐图ECDF
计划：80秒；累计 02:45—04:05。
　　八路分数不能简单相加。有的模型分数集中在中间，有的接近零或一，直接加权，实际作用就会受到分数尺度影响。
　　我们的做法是先做ECDF映射，把每一路分数转成参考集合中的排序位置，再分成图中的三个槽。四个CLIP-H和SigLIP2等权进入主槽，两个低分辨率bigG进入第二槽，高分辨率bigG进入第三槽。主槽占四分之三，其余权重见图中公式。
　　三槽组合后，再按八比二加入尺寸先验，最后做一次ECDF映射。尺寸先验利用宽高、像素和文件大小，补充图像规格信息。但这类线索依赖数据分布，换场景后要重新评估。
　　推理时，参考表已经固定，一张图片也能查到自己的排序位置。因此，这个输出是检测分数，不能直接理解为“有多少概率是AI生成”。下面看这种组合的效果。

## 06｜图像效果：融合性能与分量互补
计划：60秒；累计 04:05—05:05。
　　左边的图展示四个主要配置，AUC从约零点九零八提高到约零点九一九，最后两组相差约零点零零一五。这些配置同时调整了基底、权重和训练安排，所以这里展示的是选型结果，不能把提升全部算到某一个设计上。
　　右边再看分量之间的关系。四路CLIP-H的排序比较接近，平均相关约零点九六；主CLIP-H与SigLIP2、以及高分辨率bigG的相关更低，说明它们提供了不同判断。
　　但判断不同，还要有足够的检测能力。我们同时考虑单路效果、分量互补和计算成本，最终保留八路。图像部分讲到这里，接下来介绍文本。

## 07｜文本：目标域自训练
计划：80秒；累计 05:05—06:25。
　　文本侧同样是一千条官方标注，加两万条无标签目标文本。关键是把已有检测分数变成训练信号。
　　请沿左侧实线看：上一代检测器先给两万条文本打分，分数转成排名，再由sigmoid生成软标签。左侧八百条官方硬标签汇入加权损失，软标签同时带上置信权重。冻结语言基座后，更新LoRA和分类头。
　　右边实线表示软标签，范围约零点一二到零点八八；虚线表示权重，中间最低、两端最高为一。官方硬标签权重为二，提供真实监督。这些权重直接作用到二元交叉熵损失。
　　流程图右侧，中间的每折两百条只用于验证，AUC选择检查点；下方的五折折外预测用于融合选型。这样利用目标域数据，也减少中间样本的监督强度，但不能保证教师错误不会传播。下面看最终模型。

## 08｜文本：两基座，15个适配器
计划：70秒；累计 06:25—07:35。
　　最终方案以Qwen2.5十四B为主、七B为辅。请从模型树上方往下看：两个共享基座，分出三组五折。十四B主分支有五个适配器；七B两个辅助分组各有五个，共十五个。两组七B并不是一次十折验证。
　　推理时，基座常驻，适配器依次切换。十四B运行五次，七B运行十次，底部先分别聚合，再按百分之九十和百分之十汇合。
　　再看右边的结果：十四B五折组合已经达到约零点九八一一，加入七B后约为零点九八一三，提升约零点零零零二三。这个收益需要和额外计算一起衡量。因此，辅助分支是否保留，要看它能否补充主模型的判断。下一页解释同一套模型如何处理整批数据和单条请求。

## 09｜文本：批排名与单条推理
计划：60秒；累计 07:35—08:35。
　　这里有两条计算路径。左边沿三个rank节点往下看：各组预测先转成排名百分位，再以九成、百分之五、百分之五汇合，最后对整批结果重新排名。
　　右边从顶部输入往下看，在线服务一次只收到一段文本。十四B的五个logit，也就是模型原始输出，先平均，再做sigmoid；七B的十个logit也共同平均，再做一次sigmoid。两侧分数最后才按九比一加权。
　　这个顺序很关键，平均和sigmoid不能交换。这两条路径使用的计算空间不同，也就不能直接认定检测效果相同。在线输入还会截断到五百一十二个token，因此实际评测要对应服务的计算方式和输入条件。下面汇总两条链的结果。

## 10｜双赛道检测结果
计划：60秒；累计 08:35—09:35。
　　这页是最终的两项结果：图像赛道AUC为零点九一八八八七，文本赛道为零点九八一三零一，分别对应两条检测链的复赛离线结果。
　　图像侧结合异构骨干、目标域蒸馏和百分位融合；文本侧结合教师软监督和主辅语言模型，得到图中所示的整体检测效果。
　　这里要说明，AUC衡量的是排序判别能力，不是准确率，也不对应某一个固定阈值。真正使用时，还要看误报和漏报，尤其是正常人工内容被误判的代价。因此，这两项结果是检测基础；进入具体场景，还需要进一步选择阈值。接下来讨论多场景和鲁棒性。

## 11｜多场景与对抗鲁棒性：机制和适用范围
计划：60秒；累计 09:35—10:35。
　　多场景和对抗鲁棒性，要同时看训练策略与专项测试。图像加入JPEG和翻转增强，目的是减少对固定呈现方式的依赖；文本已有改写训练探索，尝试应对表达变化。
　　但有这些策略，还不能直接说已经覆盖各种攻击。目前还缺少完整、独立的分组评测。对于未见生成器、不同压缩裁剪、不同改写强度和长文本，需要分别测量性能下降。
　　已有结果也提醒我们，增加模型不一定提高效果，前面展示的双十四B种子组合就低于五折配置。尺寸先验会受图片规格变化影响，文本截断可能丢失尾部线索。这些都是部署时需要重点检查的条件。下面看效率和资源配置。

## 12｜检测效率与资源配置
计划：75秒；累计 10:35—11:50。
　　部署时，两条链都共享基座、顺序切换分量。图像完成八路打分，文本执行十五个适配器前向。服务用互斥锁保护共享参数，避免请求相互覆盖。
　　图像的已有测试，是两百张图片顺序HTTP请求，共四十七点二秒，平均每张零点二三六秒。文本是五条测试输入，以短文本为主，其中包含空串，HTTP均值零点六八秒。两组条件不同，文本测量来自宿主GPU，不能直接比较，也不能据此推算并发吞吐。批量预测还需要单独测量完整集成的总耗时。
　　计算精度上，图像服务用fp16，特征转fp32进入分类头；离线批量预测用bf16 autocast。文本CUDA加载用bf16。
　　实际部署还要在目标设备上测显存、不同输入长度下的延迟，以及排队后的稳定性，再决定是否裁减分量或扩容。最后看这些检测分数怎样服务具体应用。

## 13｜从检测分数到内容审核辅助
计划：60秒；累计 11:50—12:50。
　　我们的方案特点，是把异构表征、目标域软监督和逐条推理组合起来。它既利用不同模型的判断，也把目标数据的信息纳入训练和融合。
　　应用上，可以让图片和文本分别评分，帮助内容平台、素材筛查安排审核优先级，再由人工处理高风险和边界内容。这是我们考虑的应用路径。
　　落地时，阈值要根据误报成本来选，不能直接设为零点五。如果场景更重视保护正常创作，就先确定可接受的误报率，再看生成内容的召回。同时监控来源、尺寸、语言和风格变化，必要时重新校准模型与参考表。我们计划先用代表性的业务数据评估，再做小范围试点。最后总结三点。

## 14｜核心结论
计划：30秒；累计 12:50—13:20。
　　第一，图像和文本分别建模，用不同骨干补充检测线索。第二，用目标域软标签和分数融合，结合有限标签与无标签数据。第三，用共享基座和逐条推理，连接检测方法与应用场景。后续会继续围绕检测效果、计算成本和分布变化优化方案。我们的汇报到这里，谢谢各位评委，欢迎提问。

## 注解汇总（按页对应，不口播）

### 通用符号速查
★ rank01 与分数同向:名次从最小分数数起 → 分数越高 rank01 越大 = 越像 AI;0.5 = 正中间。
· σ = sigmoid 1/(1+e^−z),压到 0~1;σ(0)=0.5
· logit = 未过 sigmoid 的原始分;文本取 logits[:,0]
· rank01 = 名次/(N+1);最小 1/(N+1)、最大 N/(N+1),不贴 0/1
· ECDF = "分数 ≤ x 的占比";与 rank 数值相等,可预存查表 → 支持逐条查询
· ρ = Spearman 秩相关;AUC = 排序判别力(0.5 随机 / 1.0 完美)
· adapter = LoRA 增量文件(40~100 MB),挂冻结基座,切换即换模型
· epoch = 数据过几遍;batch = 一次喂多少;fold = 交叉验证的一份
· fp32 / fp16 / bf16:fp32 标准;fp16 快但范围窄;bf16 范围同 fp32、尾数短
· 【用词】LoRA 首次说"低秩适配,冻结基座只训低秩参数",之后说"适配器";忌"微调适配""适配层"
· 【用词】"微调"仅用于家族对比:微调类分支 vs 冻结表征探针

### 模型名速查
★ 三骨干均为视觉 Transformer;H=Huge 档,14=patch 14×14;LoRA=低秩适配,产物叫适配器。
· CLIP = 对比语言-图像预训练;4 亿图文对对比学习 → 我们当视觉特征提取器(冻结)
· ViT = 视觉 Transformer;图切块当"词",不用卷积
· CLIP ViT-H-14 = Huge 档 ViT + patch14;权重 laion2B-s32B-b79K,632M,冻结;主槽 4 分量
· CLIP ViT-bigG-14 = 比 giant 大一号(约 2.5B,含文本塔);bigG@224 槽 2 + bigG@384 槽 1
· SigLIP2 = Sigmoid 语言-图像预训练第二代;so400m = 400M 档;384 = 输入分辨率
· SigLIP 用 sigmoid 损失(逐对独立);CLIP 用 softmax 对比损失(需 batch 内归一化)
· 224² ≈ 256 token;384² ≈ 729 token → 注意力按平方涨,换分辨率 = 换视角
· LoRA:微调 ⊃ PEFT ⊃ LoRA;W′ = W + (α/r)·BA,W 冻结,只训 A/B
· 【误读】H ≠ High;14 ≠ 层数;LoRA 不增层(增层的是经典 Adapter)

### 名词与方法速查
★ 三个易被追问:LightGBM(树模型,非神经网络)、转导(用了待预测数据本身)、OOF(折外预测)。
· 异构表征 = 用【多种不同来源的表征】做判断,而不是单一模型。拆开看:
　表征 = 模型把原始输入(像素 / 文字)转成的内部特征;异构 = 架构 / 训练目标 / 输入规格 / 监督方式彼此不同
　图像侧:3 类骨干(CLIP ViT-H-14、bigG-14、SigLIP2)× 输入 224 与 384 × 训练方式(转导蒸馏 / 纯监督)× 数据(Tiny-GenImage / GenImage++ / 测试集软标签)
　文本侧:14B 与 7B 两个规模;教师六路里还含树模型(LightGBM)、冻结探针(逻辑回归)、零训练的似然差
　为什么有价值:不同骨干的归纳偏置不同 → 对同一扰动的敏感方向不同 → 犯错不相关 → 融合可降方差并补盲区
　实测支持:同配方换种子的相关(CLIP-H 四路 0.960089、bigG@224 两路 0.835688)明显高于跨架构相关(主 CLIP-H ↔ SigLIP2 0.7914、↔ bigG384 0.7091)—— 说明跨架构确实更互补
　【注意】两个必须说清的限定:① 融合发生在【分数 / 秩空间】,不是特征拼接 —— 各分量各自出分,再按 ECDF + 槽权重融合;② “异构”是设计动机,其增益【未经受控消融与显著性检验】,且“互补 ≠ 必然提升”(双 14B seed 0.980896 < 14B p4 五折 0.981069)
· 【术语坑·必读】“离线 / 在线”在本方案里指【批处理 vs 逐条实时】,不是【断网 vs 联网】:
　离线(批量)= 一次拿到全部 20000 条,可用全局排名 → 产出提交 CSV(复赛成绩来源)
　在线(逐条)= 一次只收到一条,只能用当前输入 → 就是镜像的 HTTP 服务
　⚠️ 而镜像其实是【运行期零联网】的 —— 按网络意义讲它才是“离线”;两个“离线”不是一个意思,别混
　✅ 答辩首选说法:【批量提交链路】/【镜像服务链路】,或【批量评分】/【逐条 HTTP 推理】;若说了“离线”,紧跟一句“这里指批处理方式,不是网络状态”
· LightGBM = 微软开源的梯度提升决策树;GBDT/GBM = 决策树串行拟合残差;不需 GPU
· 逻辑回归 = 线性 + sigmoid;参数少 → 适合当冻结表征的探针
· n-gram = 连续 n 个字/词;字符 2–5 gram 对中文有效且抗改写
· TF-IDF = 词频 × 逆文档频率 → 稀疏向量
· 风格特征 = 长度/行数/平均行长/字符类别占比/去重字符率("怎么写")
· 似然落差 = 两模型对数概率之差(长度归一),抵消长度与主题
· 转导 = 训练用到待预测数据本身;代价:该数据上的成绩不代表泛化
· 蒸馏 = 学生拟合教师输出;自蒸馏/迭代自举 = 教师是上一代自己
· 软标签 = 0~1 连续目标;硬标签 = 人工 0/1
· OOF = 每折验证样本由"没见过它"的模型打分;过拟合 = 背下训练集
· corr = 相关系数(−1~+1)。皮尔逊 np.corrcoef 看数值;斯皮尔曼 spearmanr 只看排序。仓库写 rank corr 必指后者;只写 corr 的(anchor 0.96、基底↔主分量 0.9758)原文未标明,照说即可
· 本任务只看排序 → 秩相关为准;0.99 ≈ 排序几乎相同,0.96 ≈ 高度相似,0.83 ≈ 偏低
· rank 归一化 = 分数换名次百分位。四作用:尺度统一(否则 9:1 被数值大的那路绑架)、与 AUC 一致、免疫未校准与极端值、可跨模型比较。三代价:须整批才能算(离线≠在线的根源)、相对指标、丢失绝对间隔
· 骨干 = 冻结的预训练主体;分类头 = Linear(1024,1) + sigmoid
· 【冻结骨干是干什么的】骨干承载预训练知识(CLIP 见过 4 亿图文对、Qwen 见过海量文本);冻结 = 训练中一个数都不改。四个理由:
　① 保留预训练参数:每折只有 800 条官方样例,全量更新存在遗忘通用能力的风险,具体程度取决于数据与训练配置
　② 控制过拟合风险:14B / 632M 参数全量微调的可训空间很大;少标签下限制更新范围是一种取舍,不等于全量微调必然记忆训练集
　③ 让“适配”发生在小参数空间:可训的只有 LoRA + 头,图像侧仅 15.73M(2.5%)

　【要说清】冻结不是“省显存”的妥协,而是设计选择:它把“学什么”限制在低秩增量上

### 第 05 页｜图像融合：三槽计算与逐图ECDF
★ 顺序:分量 ECDF → 三槽 base → z = 0.8base + 0.2prior → 末次 ECDF;base 不做 ECDF;主槽 5 个分量。
· s_i → p_i = F_i(s_i):逐符号读 —— i = 分量编号(1~8);s_i = 该分量的【原始分】(未归一化,八个分量量纲各不相同);
　F_i = 该分量【自己那份】ECDF 表(预先在 20000 张上算好、存盘,逐图查表);p_i = 查出来的百分位(0~1),也是后面所有加权的实际输入
　【作用】把 8 个【量纲各异】的原始分统一到同一把尺子(0~1 百分位)—— 这是它们之后能相加的前提;不统一就没法按权重融合
· ECDF 式 F_ref(x) = (lo+hi+1) / (2(N+1)):逐符号读 —— ref = 参考数组(该分量在 20000 张上的分数);N = 20000;
　lo = 参考数组里【严格小于】x 的个数;hi = 【小于等于】x 的个数(并列的都算进来);x 就落在 lo 与 hi 之间
　分子 lo+hi+1 = 并列样本【平均秩的两倍】:并列时取 (lo+1+hi)/2,通分即 (lo+hi+1)/2;分母 2(N+1) 里的 2 正是通分带出来的
　所以整式 = 平均秩 ÷ (N+1),与 rankdata(x,'average')/(N+1) 逐位相等 —— 这就是“逐图 ECDF 与批 rank 恒等”的来源
　【那个 +1 不可省】指分子的 lo+hi+1:并列取平均秩必须有它;省掉会出现 0.5/(N+1) 的常数偏移(排序不变,但数值不等)
　【作用】让“百分位”【逐图可算】—— 服务端一次只收到一张图,算不出全局排名;这个式子只依赖预先存好的参考表,所以镜像能对单张出分,而且与离线批 rank 排序一致。它就是把“交付形态(逐条)”与“算法(全局排名)”接上的那座桥
· 【整条链的量纲】公式里每一步都是“ECDF 百分位”(0~1):p_i(分量百分位) → m(槽内平均) → base(槽加权和) → z(再与先验加权) → score(末次 ECDF)
· m_H、m_B、m_384 是【槽内平均值】,不是原始分数 —— 参与平均的是各分量的 ECDF 百分位:
　m_H = 主槽 5 个成员(4 个 CLIP-H 的 H₁..H₄ ＋ SigLIP2 的 S)百分位的等权平均(H 取自 CLIP-H)
　m_B = bigG@224 槽两个分量(B₁、B₂)百分位的平均
　m_384 = s384 槽只有 1 个分量,所以直接等于它的百分位(B₃₈₄),不需要再平均
　【作用】槽内平均 = 【降方差】:同配方只换种子的分量几乎重复(ρ≈0.96),先平均可避免同一份信息被重复计分,同时压低随机波动
· base = (3/4)m_H + (1/7)m_B + (3/28)m_384;0.75 + 0.142857 + 0.107143 = 1
　【作用】槽级加权 = 【按互补性分配话语权】:相关低的槽(跨架构)单独成槽拿到独立权重,而不是被并进主槽淹没
· prior 就是【尺寸先验的百分位】(代码里叫 prior_pct,值域 0~1):只用图片规格算出的一路信号,内部经“桶 + GBM 混合 → 再 ECDF”才得到它(细节见下方几条)
　它已经是 0~1 的百分位,与 base 同量纲,所以能按 0.8 / 0.2 相加
　【作用】引入一路【与模型近乎不相关】的强信号(与模型 ρ 仅 0.146、自身 OOF AUC 0.8247)去补模型盲区 —— 这正是“异构”在分数层面的兑现
· z = 0.8·base + 0.2·prior;score = F_final(z)(全程只此一次 ECDF,且只作用于 z,base 不做 ECDF)
　【作用】后融合(先各自出分、再按权重相加)= 不把外部尺寸先验学进模型,权重可事后调、可解释;末次 ECDF = 把融合结果【再变回统一百分位】,输出尺度一致且与 AUC 天然对齐
· 桶 = 按精确分辨率(宽×高)分档;官方 1000 张共 43 个分辨率 = 43 桶
· 桶值 = 该分辨率下的标签均值;未见分辨率回退全局均值
· 收缩平滑 sm = (均值×n + 全局均值×5) / (n+5):均值 = 该桶标签均值;n = 该桶样本数;5 = 【伪计数】(相当于先塞 5 个“全局均值”样本)—— n 越小越被拉向全局,防小桶过拟合
　【作用】小桶收缩:n 小(该分辨率样本少)时向全局均值靠,防小桶过拟合 —— 43 桶里有不少只有几张图
· 桶ECDF = 桶值那一路(0.4);GBM ECDF = 概率那一路(0.6)
· 先验三段:桶 0.818892 + GBM 0.819480 → 0.4/0.6 混合 0.824702 → 再 ECDF
· 【这张图的作用】它不是成绩,是【先验这个小模块自己的体检报告】;三根柱回答两个问题:
　① 只用图片规格(宽/高/像素/字节)做题就有 0.82 的 AUC → 规格分布确实携带信息,这路信号不是噪声

　【必须限定】这是官方 1000 张上的 5 折 OOF 值,只说明这批样例;本质是利用数据集构建偏差(shortcut learning),跨来源不一定成立 —— 主动披露
· GBM 9 特征:宽/高/宽高比/像素/字节/bpp/是否方形/短边/长边(前 5 类取 log1p)

　实线 y(r):教师给排名 r,按 σ(4(r−0.5)) 变软标签 —— 单调 ⇒ 次序完整保留;值域 0.1192~0.8808,【刻意到不了 0/1】,不把教师的判断当成铁律
　虚线 w(r):由同一套排名算出训练权重 —— 教师【犹豫的样本权重压到 0】,两端饱和到 1;分界点 .2253 / .7747 就是令 |y−0.5| = 0.25 反解出来的

· 损失 L = mean[w·BCE(z,y)]:z = 学生输出;y = 软标签;w = 上面的权重;mean = 对样本取平均 → 即先按样本加权、再平均,【不除以权重和】
　BCE(z,y) = −[ y·log σ(z) + (1−y)·log(1−σ(z)) ]:σ(z) = 把 logit 压到 0~1;y 是软标签(0~1 之间),所以是“软”的交叉熵
　【作用】逐样本加权再平均,把权重作用到损失。与除以权重和相比,同一batch的梯度尺度不同;优化器和batch权重变化时,不能直接等同于固定缩放学习率

### 第 09 页｜文本：批排名与单条推理
★ 离线"先排名再融合";在线"先平均 + sigmoid 再融合";σ 与均值不可交换 → 两链不保证同排序。
· 左(整批):各分支在 20000 内取排名 r14 / ra / rb → 0.9r14 + 0.05ra + 0.05rb → 再排名(0.05 = 7B 那 0.10 的一半,平分给 r3a / r3b 两条谱系)
　【作用】左是复赛批量提交的计算路径,利用目标集合排名;没有同条件有标签对照,不能称为逐条链路的精度上限。图中分支预测已包含各自逐折聚合,不能替换成rank(raw mean)
· 右(单条):14B 5 个logit平均→σ;7B 10个平均→σ;再0.9p14+0.1p7(p14/p7为sigmoid分数,未校准为生成概率;σ输入截断到±30)
　【作用】右逐条可算。两链同时改变排名与logit聚合空间及运算顺序;不能把观察到的全部排序差异只归给sigmoid与均值不交换
· logit 平均是什么:逐个适配器各跑一次前向,取输出里第 0 号 logit(= AI 方向),累加后除以适配器个数
· 源码(_mean_logit):`model.set_adapter(nm)` 切适配器 → `s += logits[0,0]` → `return s / len(names)`
· 于是 14B 得 5 个 logit 的均值、7B 得 10 个的均值;各自 sigmoid(内部把 x 截断到 ±30 防溢出),最后 0.9/0.1 加权
· 为什么不在概率上平均:先平均 logit 再 sigmoid ≠ 先 sigmoid 再平均(sigmoid 非线性)—— 顺序不同结果就不同
· 聚合空间不同:左 = 秩空间,右 = logit 空间
· 已量化:两链排序相关 ≈ 0.99987;排序变化 0.10929%(218,571 对);无真标签 → 不能换算成实测 AUC 差
· 在线输出非校准概率;输入截断 512 token
