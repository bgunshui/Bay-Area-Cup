# 文本镜像与离线提交差异说明（核对修订稿）

> 2026-10-02依据代码与当前交接文件修订。本文为可供负责人审核的说明稿，不代表已向组委会发送的历史邮件；历史版本保留在Git中。

## 一、目前可以确认的结论

离线提交生成代码和服务代码采用不同的聚合与映射方式，因此不保证同排序、同AUC。当前冻结online数组与提交CSV的Spearman约0.9998697006，高相关不能证明AUC不变，也不能排除实现问题。

最终提交文件为[submit_p4_90_7b2_10.csv](../submission/submit_p4_90_7b2_10.csv)，已确认最终文本AUC为0.981301。提交时间、状态及名次仍需官方凭证；0.981301不能直接写成镜像独立评测成绩。

## 二、代码里的两条公式

根据[p97](../code/fusion/p97_p4_7b_sweep.py)，记r为平均秩除以N+1：

```python
p4 = r(load("lora14b_p4_replay.npy"))
a  = r(load("lora7b_distill_r3a_replay.npy"))
b  = r(load("lora7b_distill_r3b_replay.npy"))
offline = r(0.90 * p4 + 0.10 * (a + b) / 2)
```

根据[server_dual_v4.py](../code/docker_submit/server_dual_v4.py)：

```python
online = 0.90 * sigmoid(mean(14B_p4_5_logits)) \
       + 0.10 * sigmoid(mean(7B_r3a_r3b_10_logits))
```

离线replay来自逐折排名与聚合；服务直接平均logit后映射。不能说“折聚合完全相同”或“唯一差异只是最后一步rank换sigmoid”。rank有并列时不严格均匀，sigmoid分数也未经概率校准。

逐条处理未知集合无法现场获得完整集合排名。当前服务采用sigmoid替代，是实际实现的选择，不能声称所有其他设计都不可能或差异绝无缺陷。

## 四、仍需分别核实的实现与交付问题

两基座、p4五折和r3a/r3b两组各五折的路径与0.90/0.10权重可在源码中核实；最终运行过的权重、方向、完整输入与日志尚未建立可逐项核验的版本关联。p43的预测方向翻转只作用于数组，若曾触发，部署adapter方向需另核。

v4仍有NaN裁剪顺序、缺adapter未强制数量校验、设备迁移缺最终断言等风险，不能将偏差概括成“不是模型、权重或推理代码错误”。

本次收到的旧tar是约44.49 GiB、v2服务；交接方说明的新tar约49.66 GiB、SHA以a163a653开头，尚未提供本地。不能用新镜像说明替代实际收到的旧文件检查。

GPU报告是团队提供的chroot/宿主机测试摘录，仅五条短文本，缺完整原始日志，并非本次实际docker load/run。不能据此保证全部样本和平台资源下的性能。
