## 一、结论

该偏差属于**方案实现层面的必然差异,不是模型、权重或推理代码的错误**。

原因是:我们**复赛最优提交(0.981301)采用的是"全局排名归一化"的分数融合方式**。
这是一种转导式(transductive)运算,必须在**一次性看到全部 20000 条测试样本**的条件下才能完成;
而评测平台通过 `POST /predict` **逐条下发请求**,镜像在返回第 k 条分数时并不知道其余样本的分布,
**在协议上无法复现该全局操作**。

因此镜像内改用**逐样本可计算的 sigmoid 分数级融合**作为替代。两条链路对同一批 20000 条复赛数据的
排序相关系数为 **0.99987**,其中 **99.898% 的样本对排序完全不变**,差异仅出现在
**0.1023% 的"近乎并列"样本对**上 —— 这就是"微小分数差异"的来源。

> 直观解释:离线是把两个模型的输出各自换算成"在全体样本中的名次"再加权;
> 线上只能各自换算成"概率"再加权。名次与概率的刻度不同,同一个 0.90/0.10 权重
> 所对应的实际相对影响就略有差别。

## 三、造成分数偏差的具体原因

### 3.1 离线提交的实际计算式

我们已用本地留存的全部中间结果**逐位重建**了该次提交:重建结果与提交文件
**排序完全一致,数值最大绝对差 1.1×10⁻¹⁶**(即浮点舍入量级)。
据此确认提交文件的计算式为:

```
p4   = mean_{fold=1..5}  rank01( logits_14B_p4_fold )     # 每折先在 20000 条内做全局秩归一化,再按折平均
r3a  = mean_{fold=1..5}  rank01( logits_7B_r3a_fold )
r3b  = mean_{fold=1..5}  rank01( logits_7B_r3b_fold )
ens7 = ( r3a + r3b ) / 2
score_offline = rank01( 0.90 × p4 + 0.10 × ens7 )
```

其中 `rank01(x) = rankdata(x) / (N+1)`,`N = 20000`。

### 3.2 镜像内的计算式(平台逐条调用,只能使用逐样本算子)

```
score_image = 0.90 × sigmoid( mean_{fold=1..5}  logits_14B_p4_fold )
            + 0.10 × sigmoid( mean_{fold=1..10} logits_7B_r3a/r3b_fold )
```

### 3.3 两处差异(同源)

| # | 差异 | 离线提交 | 镜像 |
|---|---|---|---|
| A | **折间聚合所在的空间** | 秩空间:每折先做全局排名,再按折平均 | logit 空间:先按折平均,最后做一次非线性映射 |
| B | **跨模型融合所用的表示** | 全局排名(强制为均匀分布,标准差恒为 0.2887) | sigmoid 概率(保留各模型的置信度尺度) |

由于 `rank01` 会丢弃各模型的分数尺度、把输出强制变成均匀分布,而 `sigmoid` 会保留尺度,
**同一个 0.90/0.10 权重在两种表示下所对应的实际相对影响并不相同**,因此融合后的样本排序
会出现上述极小比例的差别。这是方法论上的取舍,不涉及任何实现缺陷。
