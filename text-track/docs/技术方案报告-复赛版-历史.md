# 湾区杯 · AI 生成文本检测 · 技术方案报告

## 一、方案概述

本方案针对复赛阶段"生成模型多样性提升、存在人工润色与多模型混合改写"的对抗场景,
构建了一套**多轮迭代自训练 + 领域自适应**的文本检测系统。

- **复赛文本 AUC:0.981069**(复赛文本榜第 4 名)
- **核心模型**:Qwen2.5-14B-Instruct + LoRA(5 折集成)
- **训练范式**:三轮迭代伪标签自训练(transductive domain adaptation)
- **部署形态**:单容器、单模型族、离线可运行、8-bit 量化推理

---

## 二、任务理解与关键挑战

| 挑战 | 我们的观察 |
|---|---|
| **域偏移** | 官方样例集(1000 条,含大量 256×256 小图/短文本)与复赛测试集(20000 条,改写强度更高)分布差异显著 —— 直接用样例训练的模型在复赛上明显退化 |
| **改写对抗** | 复赛数据包含人工润色、多模型混合改写,基于表面统计特征(困惑度、token 概率)的检测器性能大幅下降 |
| **无标签目标域** | 复赛测试集无标签,无法直接监督训练 |
| **评估噪声** | 官方样例仅 1000 条,五折后每折仅 200 条验证样本,AUC 统计噪声约 ±0.01,不足以做模型选择 |

**核心结论**:官方样例上的验证分数**不能预测复赛表现**,唯一可靠的信号是复赛反馈。

---

## 三、技术路线

### 3.1 整体框架

```
┌─────────────────────────────────────────────────────────────┐
│ 第一轮:官方样例监督训练(fast)                                │
│   官方 1000 条 → LoRA 微调(Qwen2.5-1.5B/7B/14B)             │
│   + 多视角特征分支(LLM 似然、隐藏态、外部数据)                  │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│ 第二轮:多分支融合 + 伪标签自训练                              │
│   48 个异构分支 rank 融合(0.978284)                          │
│   → 对复赛 20000 条生成软伪标签                                │
│   → 训练 14B 学生(域自适应)                                   │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│ 第三轮:多随机种子自训练 + 异构集成                            │
│   同一强伪标签下训练多个 14B seed(仅随机种子不同)              │
│   → 复赛反馈选择最优组合(单 seed 0.981069 为最优)             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 伪标签构造(核心)

对融合后的复赛预测分数 `s`(20000 条),构造软标签与置信度权重:

```python
rank = rank01(s)                              # 排名归一化到 (0,1)
soft = sigmoid(4 × (rank − 0.5))              # 软标签,范围 (0.1192, 0.8808)
conf = clip(4 × |soft − 0.5|, 0, 1)           # 置信度权重
```

**训练样本构成**(每折):

| 数据 | 数量 | 标签 | 损失权重 |
|---|---|---|---|
| 官方训练折 | 800 | **真实硬标签** | **2.0** |
| 复赛测试集 | **20000** | **软伪标签** | `conf` |

**关键设计**:官方真标签权重加倍,保证模型不被伪标签带偏;复赛数据每折全量参与,实现域对齐。

### 3.3 模型与训练配置

| 项 | 配置 |
|---|---|
| 基座 | Qwen2.5-14B-Instruct(bf16) |
| 微调方式 | LoRA:r=16, α=32, dropout=0.05,target = q/k/v/o_proj |
| 分类头 | `score`(2 类,新初始化) |
| 损失 | `BCEWithLogitsLoss(logits[:,0], target) × weight` |
| 优化器 | AdamW,lr=5e-5,weight_decay=0.01,linear warmup 10% |
| 训练 | 2 epochs,seq_len=512,batch=2(梯度检查点关闭) |
| 交叉验证 | 官方 1000 条 5 折;复赛数据不参与验证 |
| 预测 | `logits[:,0]`(AI 方向);方向保护:AUC<0.5 自动翻转 |

**为何用 `logits[:,0]` 而非 softmax**:早期版本使用 `softmax(logits)[:,1]`,导致 **45% 的样本并列在 1.0**
(数值饱和),排序信息大量丢失。改用 logit 原值后,`frac==max` 从 **49.5% 降至 0.10%**。

### 3.4 关键实验结论(基于复赛反馈)

| 实验 | 复赛 AUC | 结论 |
|---|---|---|
| 纯 14B seed1 监督微调 | 0.9615 | 单分支基线 |
| 48 分支融合(含 LLM 似然/隐藏态) | 0.978284 | 融合有效 |
| 第一轮自训练(14B seed1) | 0.979964 | 域自适应 **+0.0017** |
| 双 seed 集成(seed1+seed2) | 0.980896 | 多 seed **+0.0009** |
| **纯 seed2(最优单一模型)** | **0.981069** | seed 间差异达 **0.0011** |
| seed2 + 异构 7B 集成(9:1) | **0.981301** | 异构混合 **+0.0002** |

**重要发现**:
1. **迭代自训练有效**:用融合模型对无标签目标域打软标签,可显著提升复赛表现(+0.0017)
2. **多随机种子集成有效**:同配置不同种子的模型集成可稳定提升(+0.0009)
3. **异构混合优于同构混合**:14B 与 7B 的集成(相关 0.995)优于两个 14B 种子(相关 0.996)
4. **伪标签的"信息多样性"比"分数"更重要**:用 48 分支融合(0.9783)训练的模型,优于用纯 14B 集成(0.9809)训练的模型

## 四、部署方案(Docker)

### 4.1 镜像设计

| 项 | 说明 |
|---|---|
| 基础镜像 | `pytorch/pytorch:2.4.0-cuda12.1-cudnn9-runtime` |
| 模型 | Qwen2.5-14B-Instruct + 5 折 LoRA adapter(全部打包进镜像) |
| 量化 | **8-bit**(bitsandbytes),显存占用 ~16GB |
| 服务 | FastAPI + uvicorn,监听 `0.0.0.0:8080` |
| 离线 | 完全离线运行(`HF_HUB_OFFLINE=1`),无任何外网依赖 |

### 4.2 推理流程

```
POST /predict {req_id, data}
    ↓
① 依次挂载 5 折 LoRA,对文本做前向
② 取 logits[:,0](AI 方向),5 折平均
③ sigmoid 映射到 [0,1]
④ 返回 {req_id, code:0, score}
```

**关键说明**:
- 离线方案使用 **rank01 融合**,但平台**逐条下发请求**,无法获得全量分布做排名归一化
- 因此线上改用 **sigmoid 分数级融合**;经 20000 条复赛数据验证,两种方式的排序相关性达 **0.999997**
  (排序差异 >0.01 的样本占比仅 0.065%),**分数预期保持不变**

### 4.3 性能与资源

| 指标 | 实测/预估 |
|---|---|
| 单条推理耗时 | **~1.5 秒**(5 折 × 14B 8-bit 前向) |
| 启动加载时间 | **~120 秒**(模型 + 5 adapter) |
| **显存需求** | **~18 GB**(8-bit 14B 权重 14GB + 激活) |
| CPU / 内存 | 8 核 / 32 GB |
| 镜像大小 | ~22 GB |

均满足标准要求(单请求 ≤90s、启动 ≤300s)。

### 4.4 接口自检

| 检查项 | 状态 |
|---|---|
| `/health/startup`(加载中 503,完成 200) | ✅ |
| `/health/liveness`(轻量,<100ms) | ✅ |
| `/health/readiness`(就绪后 200) | ✅ |
| `POST /predict`(纯文本输入,`req_id` 原样返回) | ✅ |
| `score ∈ [0,1]` + NaN 保护 | ✅ |
| 离线运行、无外网下载 | ✅ |

## 六、方案亮点

1. **完整的迭代自训练框架**:三轮伪标签迭代,每轮教师模型都在前一轮最优融合之上
2. **针对评估噪声的对策**:明确识别"官方样例不可用于模型选择",全程以复赛反馈驱动决策
3. **异构集成**:在 14B 与 7B 之间建立互补(尽管相关性 0.995,异构错误模式仍带增益)
4. **工程可部署**:单容器、离线、8-bit 量化,单条推理 1.5 秒,显存 18GB
5. **严格的数值稳定性处理**:识别并修复了 softmax 饱和问题(`frac==max` 49.5% → 0.10%)
