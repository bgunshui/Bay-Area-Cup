## 一、核对范围与方法

已对文本目录119个Python源文件建立完整解析及SHA-256清单：training 30、features 27、fusion 41、docker_submit 7、verify 14。按实际实现追踪了数据读取、监督训练、自训练、伪标签、checkpoint选择、最终CSV构造、各版服务、镜像修复与验证路径。索引见[源码核对范围](../evidence/验证输出/文本源码核对范围_2026-10-02.json)。语法解析和静态阅读不能证明所有历史脚本已成功执行，也不代表所有运行缺陷都已排除。

读取了全部9个数值npy和20000行冻结CSV。使用独立标准库解析、平均秩、融合及带并列的排序对计数；再用NumPy/SciPy检查分数与Kendall tau-b，小样例用穷举检查对数算法。没有执行原训练脚本、模型加载、pickle或镜像里的程序。

本地旧tar此前已做静态结构及小文件提取，确认其服务源码匹配v2；修复后的新tar未交接。没有重新训练、跑GPU或docker load/run。这满足本次“依据代码核对交接事实、准备文本答辩”的范围，不宣称完成模型全量复现或容器验收。

## 三、冻结数据复核结果

| 比较 vs 提交CSV | Spearman | 秩不同的行数 | 最大分数差 |
|---|---:|---:|---:|
| 旧README近似链 | 0.9999998013 | 9341 | 0.0093495325 |
| frozen offline | 0.9999995877 | 18062 | 0.0019999000 |
| frozen online | 0.9998697006 | 19369 | 0.1618774523 |

CSV SHA-256：`30da9967ebe8c33533ce63aa048df4648ef2cafea5fb7c7934b155346997c7e3`。20000行，id唯一，分数有限。数组没有id，缺原文，所以复算按提供行序进行，不能独立证明其与每条原文的对应关系。

CSV与冻结online严格反序218292对、单侧并列变化279对，合计218571对，约占全部无序样本对0.10929%。Kendall tau-b独立实现与SciPy同为0.9978162717686663。没有复赛真标签，不能计算实际AUC差，也不能从高相关直接推出AUC不变。

运行：`python text-track/evidence/核对工具/verify_frozen.py`，仅需标准库。结果：[复算JSON](../evidence/验证输出/代码事实核对_2026-10-02.json)、[排序交叉检查](../evidence/验证输出/排序对数交叉检查_2026-10-02.json)。JSON中记录的是数据来源基线与检查时间，不把生成日期当成模型训练日期。

## 四、文档修订后仍待处理的代码风险

| 风险 | 实际影响或边界 | 源码 |
|---|---|---|
| NaN先夹取后检查 | 可能返回接近1的异常分数，未可靠回退到0.5 | v4的_sig与predict |
| 缺adapter静默跳过 | 可能加载不足5+10仍进入后续流程 | v4加载逻辑 |
| GPU迁移异常被捕获 | 没有最终设备断言，源码不保证每个模型最终在预期设备 | v4加载逻辑 |
| 预测方向与adapter保存不同步 | 验证AUC<0.5时仅翻转数组；若最终折触发需核部署方向 | p43 |
| 历史flips计数 | 强制拆并列，树更新/查询下标不一致；不能沿用其对数 | analyze_final、analyze_deviation2 |
| final_check输入与路径缺失 | 当前checkout不能照旧命令直接重建 | final_check、p97 |
| 训练截断未显式启用 | 长度配置不能单独证明实际训练序列上限；预测阶段显式截断 | p42、p43 |
| “严格重训”注释不等于严格一致 | p75训练默认512，预测调用仍落到默认768；与p10默认配置不完全同一 | p75、p10 |
| 日志名sample_auc不一定是AUC | 两个特征脚本实际打印相关系数/Spearman | infer_active_text、infer_mokawa_active |
| 历史审计可能漏报 | requirements缺失、部分头解析失败未完整影响问题清单/退出码 | audit_BCD_image |
| 简单归档检查只是打印 | MATCH/MISMATCH不等于完整分层审计或可靠失败退出 | check_archive |

本次没有改这些源码，也没有声称它们在最终平台一定触发。服务锁对adapter切换提供串行保护，实际吞吐和并发排队仍需测试；7B加载失败会使readiness不成功，并没有自动退回14B的已实现保证。
