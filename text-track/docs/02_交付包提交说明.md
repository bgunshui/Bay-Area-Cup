## 二、启动方式

```bash
docker load -i ai-text-detector-0.981301.tar
docker run --gpus all -p 8080:8080 ai-text-detector:0.981301
```

- 无需任何额外参数或挂载;**容器入口即启动推理服务**
- 完全离线:`HF_HUB_OFFLINE=1` / `TRANSFORMERS_OFFLINE=1`,
  可直接 `docker run --network none` 运行
- 容器内 `CMD = ["python", "server.py"]`,`WORKDIR = /app`

## 三、接口

| 接口 | 语义 | 实现 |
|---|---|---|
| `GET /health/startup` | 模型与依赖是否加载完成 | 加载期 503,就绪后 200 |
| `GET /health/liveness` | 进程是否活着(轻量,无重活) | 恒 200 |
| `GET /health/readiness` | 是否可接收推理流量 | 就绪后 200 |
| `POST /predict` | 文本分类 | `{"req_id","data"}` → `{"req_id","code":0,"score"}` |

```bash
curl -X POST http://127.0.0.1:8080/predict \
  -H "Content-Type: application/json" \
  -d '{"req_id":"t1","data":"这是一段待检测的纯文本"}'
# -> {"req_id":"t1","code":0,"score":0.xxxx}
```

**错误码约定**(与标准一致):

| 场景 | HTTP | code |
|---|---|---|
| 请求体非法 / 缺字段 | 400 | 40001 |
| 服务未就绪 | 503 | 50301 |
| 推理内部错误 | 500 | 50001 |

> 注:标准里"缺 `req_id`"要求 400/40001。FastAPI 默认会返回 422,
> 我们在 `server_dual_v4.py` 里注册了 `RequestValidationError` 处理器改成 400 —— 已实测。

## 四、资源声明

| 资源 | 需求 |
|---|---|
| GPU 显存 | **≥ 48 GB**(必需) |
| CPU | 8 核 |
| 内存 | 32 GB(建议 64 GB) |
| 磁盘 | 约 50 GB |
| 网络 | **不需要**(完全离线) |

**为什么需要 48 GB**:两个基座模型 bf16 共 41.7 GiB(14B ≈ 28 GiB + 7B ≈ 15 GiB)
+ 15 个 LoRA 适配器 < 1 GB + 激活。我们主动放弃 8-bit 量化(见 [`03_交付说明.md`](03_交付说明.md)),
因此显存需求从量化的 ~18 GB 升到 42 GB。

## 五、耗时实测(NVIDIA RTX 4090,49,140 MiB)

| 指标 | 实测 | 标准上限 |
|---|---|---|
| 启动(41.7 GiB 权重 + 15 个适配器) | **70.1 秒**(14B 侧 44 秒) | 300 秒 |
| 单条推理(14B×5 折 + 7B×10 折 = 15 次前向) | **0.68 秒**(min 0.65 / max 0.74) | 90 秒 |
| 显存占用 | **41,868 MiB / 47.4 GiB** | — |

文本截断长度 `max_length = 512` tokens。
