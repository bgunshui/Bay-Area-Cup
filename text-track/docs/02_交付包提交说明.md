## 三、v4 接口与实现

| 接口 | 源码行为 |
|---|---|
| `GET /health/startup` | 加载或预热未完成时 503；加载失败时 503 并带错误详情；就绪后 200 |
| `GET /health/liveness` | 恒 200；只表示 HTTP 进程可响应，不证明模型可用 |
| `GET /health/readiness` | `ready=True` 时 200；否则 503 |
| `POST /predict` | 必填字符串 `req_id` 与 `data`；成功返回 `req_id`、`code=0`、`score` |

| 错误场景 | HTTP | code | 说明 |
|---|---|---|---|
| 请求体非法 / 缺字段 | 400 | 40001 | v4 注册校验处理器；此响应 `req_id=None` |
| 未就绪 | 503 | 50301 | 回传有效请求的 `req_id` |
| 推理异常 | 500 | 50001 | 返回异常类型，不记录推理堆栈 |

v4 使用 14B p4 的 5 个适配器和 7B r3a/r3b 各 5 个适配器；每条文本完整配置下执行 15 次前向。各模型先平均第 0 个 logit，再 sigmoid，最后按 0.90/0.10 融合。它是检测分数，不是经校准的生成概率。超过 512 tokens 的输入会截断。

源码已加入明确 GPU 放置、整次预测锁、空分词结果 EOS 兜底及预热后就绪。锁使推理串行执行，不能当成高并发吞吐证据。

## 五、残留风险与交接核验

- v4 的 NaN 检查放在分数夹取之后，sigmoid 内也先夹取；非有限值可能变成边界分数，不能声明 NaN 保护已经有效。
- 适配器目录缺失时会跳过，未校验必须为 5＋5＋5；`ready=True` 不能证明方案完整。
- GPU 搬运兜底失败会打印异常并返回模型，未强制断言最终设备。
- 不完整的日志、结构校验或五样本烟测不能替代 Docker 运行与全量结果复现。

当前已经核对源码版本、旧镜像静态内容及验证脚本的覆盖范围。下一步交接需要正确最终镜像及其 SHA256、实际运行代码哈希、完整 GPU 驱动输出与服务日志；拿到后核对 manifest / 层 / 15 个适配器，再进行 Docker 实跑。离线与线上算法差异见 [04_镜像复现偏差说明-回组委会.md](04_镜像复现偏差说明-回组委会.md)。
