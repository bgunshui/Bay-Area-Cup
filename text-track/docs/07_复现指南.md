## A. 用冻结分数检查融合链

### A1. 先区分三类结果

| 被比较的结果，与冻结提交 CSV 对照 | Spearman | 平均秩不同的行数 | 分数最大绝对差 |
|---|---:|---:|---:|
| 旧 README 公式：p4 rank + 对 7B raw 均值分别再排名 | 0.9999998013291245 | 9341 | 0.009349532523373782 |
| `fusion_offline_submitted.npy` | 0.9999995876983739 | 18062 | 0.0019999000049997218 |
| `fusion_online_image.npy` | 0.9998697005807854 | 19369 | 0.16187745228790362 |

这些是对当前入库数组与 CSV 的直接比较，**均不满足逐位重建或排序完全一致**。高相关性说明接近，不能用来宣称完全相同；文件名含 `submitted` 也不能代替数值核对。

提交 CSV 与数组之间的排序比较不需要复赛标签。复赛 AUC、准确率及线上与离线的实际 AUC 差值需要真实标签，当前不能独立计算。

### A2. 仓库内的核对入口

优先使用新增的[标准库核对工具](../evidence/核对工具/verify_frozen.py)，在仓库根运行：

```bash
python text-track/evidence/核对工具/verify_frozen.py
```

它无需第三方依赖，读取冻结资产后更新 `evidence/验证输出/代码事实核对_2026-10-02.json`，不修改原始 CSV/npy。已保存的[核对结果](../evidence/验证输出/代码事实核对_2026-10-02.json)与[排序对数交叉检查](../evidence/验证输出/排序对数交叉检查_2026-10-02.json)可直接查阅。

如需完全只读的短示例，使用下面的比较代码。保持与被核对旧README相同的括号顺序，避免浮点舍入对并列分数排名的影响。

在仓库根目录、已有 numpy/scipy/pandas 的环境中运行以下代码。它只读文件并打印结果，不训练模型、不覆盖提交文件：

```python
from pathlib import Path
import numpy as np
import pandas as pd
from scipy.stats import rankdata, spearmanr

root = Path("text-track")
pred = root / "evidence" / "离线预测"
ref = pd.read_csv(root / "submission" / "submit_p4_90_7b2_10.csv", float_precision="round_trip")["score"].to_numpy(float)

def rank01(x):
    return rankdata(np.asarray(x, np.float64), method="average") / (len(x) + 1.0)

p4 = np.load(pred / "14b_p4_replay_rank01.npy")
a = np.load(pred / "7b_r3a_replay_raw_mean.npy")
b = np.load(pred / "7b_r3b_replay_raw_mean.npy")
approx = rank01(0.90 * rank01(p4) + 0.10 * ((rank01(a) + rank01(b)) / 2.0))
checks = {
    "raw_mean 近似输入链": approx,
    "保存的离线数组": np.load(pred / "fusion_offline_submitted.npy"),
    "保存的线上数组": np.load(pred / "fusion_online_image.npy"),
}
for name, score in checks.items():
    assert score.shape == ref.shape
    changed = np.count_nonzero(rankdata(score) != rankdata(ref))
    print(name, "Spearman=", spearmanr(score, ref).statistic,
          "平均秩不同=", changed, "最大绝对差=", np.max(np.abs(score - ref)))
```

无 id 的数组还依赖原始生成顺序；行数相同不能独立证明它们与某一份原文/id 清单完全同序。

### A3. 原提交源码需要什么

[p97_p4_7b_sweep.py](../code/fusion/p97_p4_7b_sweep.py) 读取每个 seed 保存的 `replay.npy`，先做 `rank01`，再计算：

```text
p4 = rank01(14B p4 的 replay)
a  = rank01(7B r3a 的 replay)
b  = rank01(7B r3b 的 replay)
score = rank01(0.90 * p4 + 0.10 * (a + b) / 2)
```

[p43_14b_p2.py](../code/training/p43_14b_p2.py) 保存的 replay 是 `rank01(mean_fold(rank01(raw_fold)))`。逐折先排名与先求 raw 均值再排名通常不同，所以当前 7B raw 均值不能替代原提交的 7B replay 输入。

`p97` 和 `p101_verify_7b2.py` 硬编码 `D:\湾区杯\文本赛道\transfer` 等旧路径；`p97` 还依赖当前未入库的 `submit_14b_p4_only.csv` 提供 id。`final_check.py` 同样硬编码旧路径，后半段读取原文并写逐样本对照 CSV；根 README 中原样执行它，不能作为当前克隆目录的复现命令。

`analyze_final.py` 直接融合逐折 rank 均值；`p97` 则对保存的 seed replay 再排名。两份脚本的公式有差异，不能把其输出互相替代。

## B. 镜像与环境文件的用途

最终服务源码是 [server_dual_v4.py](../code/docker_submit/server_dual_v4.py)，使用 14B p4 五折和 7B r3a/r3b 各五折，共 **15 个适配器**。7B 的“十折”指两个 seed 的五折集合，不是一次十折交叉验证。

服务公式为：

```text
0.90 * sigmoid(mean_5fold(logits_14B))
+ 0.10 * sigmoid(mean_10adapters(logits_7B))
```

这是逐条服务计算链，和 A3 的离线 rank 提交计算链不同。当前三个 raw_mean 重算该服务公式，与入库线上数组的最大绝对差约 **1.25e-9**；这支持冻结分数层面的算法核对，不等于已经在真实模型与 GPU 上复跑。

镜像标识、哈希和资产说明见 [WEIGHTS](../WEIGHTS.md) 与 [镜像信息](镜像信息.txt)。当前本地旧 tar 与文档所指最终依赖补全镜像需按哈希区分，不能仅凭相同文件名判断版本。历史性能记录见 [GPU 验证报告](验证-真机GPU报告.md)，本轮材料核验没有重新执行部署或性能测试。

## D. 核心自训练的源码默认值与选择机制

| 项 | `p42_self_train.py` | `p43_14b_p2.py` |
|---|---|---|
| 基座 | `--size`默认7b，可选1.5b | 14B |
| 输出 suffix | `_p2` | `_p3` |
| 标签文件 | `pseudo_best` | `pseudo_best_v2` |
| seed | 20260906 | 20260909 |
| epochs / batch | 2；7B为4、1.5B为8 | 2；`--batch`默认4 |
| 长度参数 | 512 | 512 |
| 梯度检查点 | 开启 | 默认开启；传 `--no-grad-ckpt` 才关闭 |
| AdamW lr / weight_decay | 7B为5e-5、1.5B为1e-4；0.01 | 5e-5；0.01 |
| 标签与损失 | 真标签权重2.0；软标签 `conf`；`BCEWithLogitsLoss(logits[:,0], target)` 的逐样本损失乘权重后求 batch 均值 | 同左 |
| LoRA | r=16、alpha=32、dropout=0.05，q/k/v/o_proj | 同左 |

默认值是当前源码事实，**不等于最终 p4/r3a/r3b 的实际运行参数**。当前缺这些最终候选的完整命令、seed映射、配置快照及执行日志，不能统一写“batch=2、关闭梯度检查点”，也不能虚构最终 seed 数值。

训练数据集的 `tokenizer.encode` 传入长度参数但未显式设置 `truncation=True`；预测编码显式启用截断。文档中的512是配置意图，不能仅据参数名保证所有实际训练序列都被相同方式截断。

### D1. 伪标签公式

```python
rank = rankdata(scores, method="average") / (len(scores) + 1.0)
soft = sigmoid(4 * (rank - 0.5))
conf = clip(4 * abs(soft - 0.5), 0, 1)
```

`rank`在(0,1)，因此 `soft` 约落在 **(0.1192, 0.8808)**，不是(0.08,0.92)。这是基于排序的软监督与启发式权重，不是校准后的真实概率；提高真标签权重能降低错误伪标签影响，不能保证模型完全不受误差传播影响。

### D2. 样例验证确实参与训练与候选处理

`p42/p43` 每轮计算官方验证折 AUC，并恢复最佳 epoch 的状态；方向保护也根据该验证折决定是否翻转预测。`p4_fusion.py` 还使用 OOF AUC 搜索家族内和家族间权重。

因此可以说“小样例验证对复赛泛化和微小候选差异的判断有限”，不能说“官方样例从不用于选型”“用样例选型必错”或“只有榜单才可靠”。五折在样例集上进行，全部无标签目标域样本加入每个训练折，这是转导式训练设置。

### D3. 从零重训仍需补齐的内容

- 原文、教师输入、三代伪标签、外部语料/公开检测器版本，以及实际分支输出。
- p4/r3a/r3b 的训练命令、seed/标签映射、长度与batch参数、检查点设置、运行环境与日志。
- 原来的目录布局及部分 `wanqu_first_submission` 模块；该模块未在当前仓库提供。
- 逐折 raw/replay 与 seed replay 文件及其对应 id 顺序、模型权重和校验值。

`p42/p43` 会在同名折 replay 文件存在时跳过训练；缓存判断没有核验当前 seed/标签参数。复用同一 suffix 后只改变 seed，不能据此认定已训练一个新候选。

`p43` 方向保护翻转的是导出的预测值，保存 adapter 时未显式把这一翻转写入分类头权重。若某折触发保护，服务使用的分数方向需结合该折运行记录核对，不能直接假设适配器已经吸收翻转。

## E. 指标、历史结论与规则说明

早期 CE 分类器有 `softmax(logits)[:,1]` 与 `logits[:,1]-logits[:,0]` 等输出；p42/p43 的 BCE 学生训练 `logits[:,0]`。输出约定应和训练目标、标签方向匹配，不能泛称所有 softmax 都错误。历史饱和比例49.5%/0.10%目前缺对应旧预测和统计输入，不作为本次重新测得的结果。

`features/infer_active_text.py` 的 `sample_auc_raw` 实际打印相关系数，`infer_mokawa_active.py` 的 `sample_auc` 实际是 Spearman；它们不能当作 ROC AUC 引用。与官方反馈对应的具体实验、提交文件和指标类型应分别注明。

当前源码确认使用无标签目标域文本进行适配；规则允许范围需对应官方条文或组委会确认。“未使用商业API打标签”等完整历史行为属于团队声明，现有本地模型代码不能独立证明所有历史操作。不能把宽泛规则或当前未见调用写成无条件合规证明。
