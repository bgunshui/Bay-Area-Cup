> 最终文本AUC **0.981301** 已由交接方和答辩负责人确认。当前仓库没有官方成绩截图和复赛真标签。

## 核心计算与证据

离线[p97](code/fusion/p97_p4_7b_sweep.py)读取各组replay、排名后按0.90/0.10融合；[服务v4](code/docker_submit/server_dual_v4.py)分别平均5个14B和10个7B的logit，再sigmoid并融合。**两条链不完全等价，最终CSV的AUC不能直接作为服务AUC。**

现有9个npy和20000行CSV已独立复核。旧README用7B raw_mean替代replay的公式与CSV最大差约0.00935，排序也不完全一致；冻结offline同样不等于CSV。缺精确7B replay与逐折raw，目前不能逐位重建提交。

冻结online与CSV的Spearman约0.9998697006；考虑并列后的排序变化约占全部样本对0.10929%，不是AUC差。没有复赛标签，不能独立算AUC或保证差值不变。具体数字见[实验与复算结果](evidence/关键实验结果.md)。

仓库已收录 **83 个训练/预测日志(已脱敏，约 9.3 MB)**，含逐折 `elapsed` 与 OOF AUC，训练与推理耗时见 [docs/09](docs/09_训练与推理耗时记录.md)；但**最终各 adapter 的完整启动命令、输入版本链与哈希仍未提供**。官方样例AUC确实用于checkpoint及融合权重选择；“三轮完整闭环”“48分支都参与”“异构或多种子稳定更好”均不能只凭旧说明下结论。

## 不需要GPU的检查

从仓库根目录运行以下**新增独立复核工具**，只读CSV/数值npy，不加载模型，不执行历史实验脚本，不需要第三方库：

```bash
python text-track/evidence/核对工具/verify_frozen.py
```

输出至[核对JSON](evidence/验证输出/代码事实核对_2026-10-02.json)。工具核验文件哈希、平均秩、融合算术式及带并列的样本对排序；它不会复算官方AUC。原final_check.py依赖作者D盘目录及未提供的精确输入，不能直接当作当前仓库的“一键复现”。
